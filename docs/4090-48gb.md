# 单卡 48GB RTX 4090：低并发配置

MDMD>48GB的机器，不适用于24GB卡。它是尚未在目标硬件验收的部署候选；不能把 PRO 6000 的容量测试当作4090验证。先完成下述单题验收，再扩大评测。

## 与 PRO 6000 的区别

|参数|PRO 6000 默认|4090 48GB 默认|

|vLLM max_num_seqs|32|1，可试2|
|max_num_batched_tokens|4096|1024|
|CUDA Graph|默认行为|enforce_eager，避免图捕获开销|
|gpu_memory_utilization|0.90|0.90|
|context / compact threshold|32768 / 14336|保持不变|
|权重、thinking_budget、输出上限|原配置|保持不变|

 QAT 31B 模型、TP1BF16 激活、关闭 LoRA。约23.3GB权重文件不是运行显存估计；实际还需要 KV cache、激活、工作区等。默认单路并降低 prefill 批量以减少峰值，但无法在没有硬件测试时保证32k上下文一定能启动。eager 可能牺牲吞吐。

## 尝试两路与故障处理

OOM后才尝试 `CONCURRENCY=2`。先等待所有评测结束，再停止本仓库启动的模型服务（核对 runs/vllm.pid 对应进程），重新以 `CONCURRENCY=2 bash scripts/run_4090_48g.sh model` 启动；评测命令也要加 `CONCURRENCY=2` 并使用新的 --run。

 flock 限制，多个调度器合计不超过配置值。切换容量前必须确保所有 benchmark/runner 已结束，再删除 `${GEMMA_SLOT_DIR:-/root/autodl-tmp/gemma-eval-slots}/capacity.txt`；有其他运行任务时禁止删除。同机不要混用旧版八路 runner，也不要为不同进程配置不同槽位目录。
